## [technical] What is an N+1 query and how did you fix it?
_Also asked as:_ How do you find and fix slow database queries? / How did you diagnose your latency problem? / Walk me through your performance debugging process.

**I measure first, find N+1 patterns in slow endpoints, then batch or join queries.**
- N+1: one query per row in a loop
- Spot via slow endpoints and query logs
- Fix with joins or batching, then re-measure

An N+1 problem happens when code runs one query to fetch a list, then another query per item, which multiplies database calls. At Nimbus Pay I started from slow endpoints with a high p95, looked at the queries they ran, and found those patterns. I replaced them with joins or batched queries, then added Redis caching for hot reads, and re-measured. Together this took p95 from 900 ms to 250 ms. I always measure before and after, so I know which change actually helped.

## [technical] How does Node.js handle concurrency?
_Also asked as:_ What are common Node.js performance pitfalls? / How do you avoid blocking the event loop? / Explain async handling in Node.

**Node is single-threaded with an event loop, so avoid blocking work and manage I/O carefully.**
- Non-blocking I/O via event loop
- Avoid CPU-heavy work on main thread
- Control concurrency to protect databases

Node.js runs JavaScript on a single thread with an event loop, which handles I/O-heavy workloads well because operations like database calls are non-blocking. The main pitfall is blocking the loop with CPU-heavy work, which delays every request, so I'd move that to worker threads or a separate service. I also watch concurrency: firing too many parallel database or API calls can overwhelm PostgreSQL, so I limit it. I use async/await carefully with proper error handling. In high-volume services this matters for stability.
